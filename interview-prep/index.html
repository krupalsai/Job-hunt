Complete system diagram: how our platform works

Use this as the big picture first. Each box is one part of the system; arrows show how information moves. These notes are based on the Student Platform interview guide in this repository. Where the guide says “verify in code,” treat it as unconfirmed.

1. Main architecture

Student phone / browserRegister, upload, view status, ask support question
Admin phone / browserManage students, batches, payments
↓ HTTPS requests
Next.js app on VercelPages / React UI + server API routes (/api/...)
↓ API route checks identity and permission before protected work
Session + authorizationValidate token, look up role, restrict admin to assigned batches
Server-side business logicValidate inputs, apply rules, call integrations
↓ allowed operation only
Supabase / PostgreSQLprofiles · batches · payments · sessions · assignments · audit data
File storagePhotos, ID documents, receipts (provider/configuration as implemented)
Payment gatewayPayment attempt and verified result
Messaging servicesWhatsApp support and Telegram admin alerts
↑ response returns through API → page updates

Important: the browser is not trusted with the service-role database secret. Protected operations should pass through server-side API routes. The database role and resource permissions must be checked on the server.

2. When someone asks the WhatsApp support bot a question

Student sends messageWhatsApp
↓ webhook request

↓ accepted message

↓ structured intent

Key distinction: in the documented WhatsApp bot, AI classifies what the person is asking; application code decides the reply. Do not describe it as a general AI that freely writes every answer. If you mean ChatGPT itself, that is a separate system from this platform bot.

6. What the technical words mean

Front endThe screen and controls the user sees.
Back endServer-side code that checks rules and performs operations.
APIA defined way for one part of a system to request data or an action from another part.
API routeA server endpoint such as /api/admin/students that receives a request and returns a response.
DatabaseStructured storage. Supabase hosts the PostgreSQL database used by this project.
WebhookA service sends your server a request when an event occurs, such as a message arriving.
AuthenticationChecks who the person is.
AuthorizationChecks what that person is allowed to do.
AI intent classifierPredicts the category/intent of a message. In this documented bot, code chooses the reply.
DeploymentThe built version running for users. A GitHub commit alone does not prove the change is live.

7. Where to look in the repository

  • Original architecture and incident notes: Student Platform interview guide.
